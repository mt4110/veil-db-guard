# 02 証拠・判定・レポート

担当: 証拠/判定担当。対象: T04,T05,T13。開始条件: T03の契約確定。予定所有範囲: `src/store.rs / src/evaluator.rs / src/report.rs / tests/evidence/ / tests/evaluation/`。共有型やCLIは変更依頼にします。

## 入力

詳細設計§3/5/6/9、検証V04/V05/V14/V15/V20、固定profileとfixtureを受け取ります。ネットワークアクセスやAWS資格情報は不要です。

## T04: 証拠保存

- 新規runだけを作り、既存出力/symlink/path traversalを拒否する。
- 選択フィールドだけの正規化設定、manifest、artifact hashを保存する。
- サイズ上限、保存失敗、開始途中/取消し/中断を扱う。保存できなかったものを保存済みと報告しない。
- Unix権限と対象OSでの挙動を確認する。自由文の除外と秘密非出力を検査する。
- manifestの内部更新はatomicに行い、別run・既存証拠を上書きしない。

受入はV04/V14。秘密らしい値の検出だけに頼らず、保存可能な構造とフィールドを制限します。

## T05: 判定器

- profileに定義した必須case/pathを先に列挙し、証拠がなくてもunknownの行を作る。
- kind/target/source/epoch/config hash/時刻/前後構成照合を検証する。
- 正例のない拒否、原因不明timeout、TCP到達後の認証拒否、古い証拠、localだけ、全N/Aを反例として扱う。
- 同じ評価区間の既知違反はfail。過去のfailは履歴に保持し、現在へ無条件に持ち越さない。
- 観測と推論、実行失敗とverdict、構成適合と実接続適合を分ける。

受入はV05/V15とV20のL層。期待値は検証仕様から独立に作り、実装に合わせて緩めません。

## T13: レポート

- JSONとMarkdownに同じ判定・対象・profile・試験元・時刻・未実施・理由・次の確認を出す。
- AWS/ローカル、宣言/照合済み、前後snapshot/運用者申告の違いを表示する。
- 複数runをローカル読取だけで評価し、外部URLや埋め込み内容を取得/実行しない。
- 構造化値を適切にescapeし、秘密や任意のSDK/driverエラー本文を出さない。

受入はV05/V14/V15。入力証拠の破損・非対応schema・一部欠落も含めます。

## 引継ぎ

主担当へ、保存契約、schema/profile版、確認した反例、未実装の将来profileを渡します。ネットワーク試験器が返す情報不足は推定で補わず、必要フィールドと理由を担当へ依頼します。
