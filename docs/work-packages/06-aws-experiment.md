# 06 AWSサンドボックス実験

担当: 実験責任者。対象: T16〜T20。M3を担います。T16の追加調査に着手し、認証と限定したread-only APIを確認しました。構築・実DB試験・撤収は未実行です。[複数クラウド検証準備](../multicloud-preparation.md)に観測・費用・未解決点を記録しています。計画作成と実環境操作を区別します。

## 入力と編集範囲

T15までの実装・ローカル結果、対象行列、T12生成物、[AWS調査](../aws-findings.md)、検証V02/V03/V06〜V16/V21を使います。実行直前にAWS対応表と料金を再確認します。

予定成果はレビュー用計画と機械評価用 `experiment-plan.json`、利用者が指定した非公開の証拠保存先です。具体的account/資源ID等を含む実行計画と証拠はその非公開先に置き、必要な公開用説明だけを `docs/experiments/<experiment-id>/plan.md` へ整理します。証拠や非公開計画を公開リポジトリへ自動追加しません。設計書中の架空例を実測値として使いません。

## T16: 具体的な承認対象を作る

以下を埋めたレビュー可能な計画を用意します。

- account/region/DB/Proxy/engine/version/class、認証方式、driver版、実行元と管理経路。
- 作成する資源、IAM/SG/DB SQLの変更対象、必要権限。既存資源を含むなら区別する。
- 正例・負例・直接経路・TLS両区間・管理・更新・復旧・性能のcase/path、profile、phase/epochと、baseline/protected/fault/recovered/cleanup間の許可差分。
- 合成データのDB/schema/user、書込/cleanup対象と、削除の影響・復旧可否。
- 許可する障害注入、接続/SQL/全体期限、取消し、停止条件。
- baseline取得方法、防御経路の切替順、性能受入値・反復数。実測前に固定する。
- RDS/Proxy/storage/runner/VPN/NAT/log等の費用要素、費用上限、実行時間上限、上限監視方法。
- 片付け・復旧対象、保持する証拠と資源、失敗時の残資源の確認方法。

未定項目が実行を左右する場合は、その情報を確認します。構築、課金、DB試験、障害、削除の具体的範囲について明示承認を得てからT17以降へ進みます。計画完成後の最終承認としてまとめ、同じ承認を工程ごとに繰り返しません。

## T17: 構築と前提確認

承認範囲の新規sandboxを構築し、DB user/schema/権限を設定します。CFN/API上の状態と実行時のSQL設定を分けて記録し、アプリと同じ試験元、対象identity、全SG/endpointを照合します。baselineは経路閉鎖前か承認済みの別経路で取得し、準備後に所定の構成へ切り替えます。

失敗時は対象の状態を把握し、後続の負例を無理に実行しません。必要な停止/復旧/片付けはT20で行います。

## T18: 防御と復帰の実証

- `aws_sandbox_core_v1`のうちT18担当のcase/pathごとに正例と負例を観測する。T19の性能とT20の片付け前にprofile全体の完了とはしない。
- 認証拒否・TLS拒否・ネットワーク閉鎖を区別し、原因不明をunknownで残す。
- 15分有効期限を越える既存接続と、新規接続の更新/拒否を分ける。
- COMMIT不明、切断、取消し後の整合性と、計画内の復旧を確認する。
- 管理例外、prepared statement/pool reset/pinning、Proxy→DB TLSの証拠を確認する。
- 同一状態の比較は同じphase/epoch内で行い、前後snapshot、実行記録と運用者申告の区別を保持する。実験全体の意図したphase遷移は計画に従って別々に評価する。

必須項目にunknownが残れば部分成果として報告し、M3達成とはしません。対象・前提の変更が必要なら、その理由と新しい範囲を示します。

## T19: 性能比較

T17で取得したbaselineとProxy経由を、計画した条件で比較します。生データ、観測数、集計方法、条件差、失敗と再試行を記録します。DB/ネットワーク/負荷の条件が異なる場合は比較限界を示します。測定後に受入値を都合よく変更しません。

## T20: 復旧・片付け・総括

通常はT18/T19後、失敗・費用超過・中断時は直ちに計画に従って行います。事前承認に含まれる所有確認済みの資源だけを復旧/削除し、対象が違う場合は止めます。削除が未承認なら勝手に消さず、残対象と費用を報告して具体的な承認を求めます。

証拠、既存資源、保持指定のものを消しません。最終状態と残資源/課金継続の確認結果、再開条件、実施/未実施を残します。T18/T19/T20と同一buildのV14ローカル結果を揃え、phase別評価を集約した最終profileを評価します。

## 引継ぎ

M3の達成/部分達成、固定対象、全必須case、未検証機能、性能の条件、残資源を主担当へ返します。サンドボックスの成功から既存DB/本番一般への安全を推定しません。
