# 00 統合と共通契約

担当: 主担当。対象: T00,T03,T14,T15。タスク状態は [一覧](../tasks.md) を参照。

## 入力と編集範囲

入力は全設計書、T01/T02の対象・依存選定、各担当の引継ぎです。予定する所有範囲は `Cargo.toml / Cargo.lock / src/domain.rs / src/config.rs / src/cli.rs / src/main.rs / tests/integration/` と全体文書の状態更新です。これは未作成の予定パスであり、T03で最終構成を固定します。

他担当の内部実装を一括改変しません。共有型の変更は、呼出側とfixtureへの影響を示してから統合します。

## T00: 今回の設計文書

- 要求、基本/詳細設計、AWS一次資料、検証、マイルストーン、一般タスク、この作業設計群を作る。
- ID/リンク/依存/担当対応を検査し、独立担当による目的・判定・安全境界のレビュー指摘を修正する。
- 未決事項を解決済みと装わず、後続タスクと接続する。実装・AWS操作はしない。
- 完了条件はM0。検査結果と修正した主要事項を `docs/design-review.md` に短く残す。

## T03: 共通契約

開始条件はT01/T02完了と実装着手の合意です。詳細設計§1〜6を、Rust型・厳格な設定解析・schema fixtureへ落とします。

- 固定assessment_profileから必須case/pathを展開し、未実施をunknownとして保持する。
- run、対象、epoch、証拠種別、execution/outcome/verdictを分離する。
- 設定から任意SQL/コマンド/秘密を受けず、入力専用自由文を正規化保存から除外する。
- module間の最小I/O契約と、各担当が使える成功/失敗fixtureを提供する。
- V01と、V03/V05/V14に必要な反例を独立した期待値付きで準備する。

完了時に型・フィールド・理由コード・終了コードの固定版を各担当へ渡します。対象未対応を暗黙fallbackで隠さないことを受入条件にします。

## T14: 統合

T06/T09/T10/T11/T12/T13の完了後に、CLIから各adapterを呼び、生成物とreportまでの対象同一性を確認します。

- planは無通信、inspectは読取限定、probeは明示対象/suite/試験書込条件だけ、reportはローカル処理のみ。
- 正規化snapshot→probe→profile評価がつながるfixture統合試験を作る。
- 部分取得、誤対象、取消し、保存失敗、古い証拠、全N/A、負例未実施、認証拒否と経路閉鎖の混同を検査する。
- 現在の情報不足と過去のfailを区別し、現在評価へ無条件に持ち越さない。
- V01〜V05/V14/V15のL層と、各probeのL層の結果をまとめる。

## T15: ローカル出荷前の確認

対象OSでビルドと必要な試験、Rustのformat/lint、選定した依存の脆弱性・ライセンス確認を行います。具体的コマンドは依存と環境の確定後に記載します。CI設定が必要ならローカルで検証可能な範囲を作り、pushやremote CI実行は承認範囲を確認します。

独立担当に秘密非出力、対象限定、偽pass、書込/retry/cleanup範囲をレビューしてもらいます。ローカル結果、未実施AWS条件、実行手順を更新し、M2までを報告します。

## 引継ぎと停止条件

引継ぎは共通形式に加え、schema/profileの版と未統合変更を記載します。権限境界を越える要求や仕様矛盾が見つかったら、その部分を止めて影響する担当へ伝えます。他の独立作業まで一律停止しません。
