# 検証設計

## 目的と証拠の区分

この文書は試験仕様です。L層は実装と確認を進め、実施結果を [ローカル検証記録](local-validation.md) と [接続試験記録](probe-validation.md) に残しました。A/E/F層は未実施です。以下の表に項目があることは、その項目の完了を意味しません。

- `L`: ローカルfixture/合成データ/ローカルDB。契約と試験器の検証用。
- `A`: 承認されたAWSサンドボックスの構成・実接続。
- `E`: 承認された既存DB導入先。
- `F`: 将来の拡張。構想を保持し、現時点では未実装。

Lで成功してもA/Eの防御成立にはしません。実施場所だけでなく、何を実際に観測したかを証拠種別で残します。

## 負例を合格にする条件

### 固定評価profile

| profile | 必須検証集合 | 判定の範囲 |
| --- | --- | --- |
| `local_contract_v1` | V01〜V05,V14 | ローカル契約と試験器だけ。AWS防御は評価しない |
| `aws_sandbox_core_v1` | V02,V03,V06〜V16,V21 | 固定したAWSサンドボックス。V14はローカル秘密非出力試験の証拠を別欄で要求 |
| `existing_db_core_v1` | aws_sandbox_core_v1の集合にV17,V22を追加 | その既存DB導入先で再取得した証拠。sandbox結果で代用しない |
| `decoy_v1` | V18,V19 | 将来の隔離デコイ。T23でcaseを具体化するまで評価実装しない |
| `continuous_v1` | V20 | 将来の継続確認。T24でcaseを具体化するまで評価実装しない |

suiteは観測を実行する選択で、profileの必須集合を縮めません。各Vの必須caseとpathを対象行列から事前展開し、不足をunknownとして必ず出力します。V07/V08の負例やV09のアプリ→DB拒否等、対象profileの必須性質をN/Aにして合格にはできません。非対応機能/未実施はunknownまたは対象非対応エラーです。profileの集合を変える場合は版を更新します。

複数runの統合は詳細設計§6の条件で、同じ状態を確かめる証拠群ごとに実験区間・phase/epoch・前後snapshot・変更管理を確認します。profile全体は事前のexperiment-plan.jsonに沿って複数phaseの個別評価を集約できます。V13のbaseline比較、V11/V12の障害/復旧、V21の片付けは意図した状態変化を持つ別評価であり、全証拠のepochやsnapshot一致を要求しません。完全な構成不変を証明したとは表現しません。過去のfailも現在の評価へ無条件に持ち越さず、同じ期間・構成に対応する証拠で判定します。

認証/TLS/権限の拒否試験では、同じ対象・試験元・時点の正例で到達可能であることを先に確認します。負例が失敗しても、原因を区別できなければ該当防御はunknownです。TLS負例を認証拒否として数えません。

V09でtimeoutしただけなら「直接接続が成立しなかった」という観測に留めます。対象同一性、アプリ送信元の照合、正規経路の成功、関連する現行構成を確認し、試験範囲に限った拒否の根拠を揃えます。拒否の原因を特定できなければpassにしません。VPC外からの接続失敗をVPC内アプリの迂回防止の代わりにしません。

ネットワーク的にDBへ到達してからDB認証で拒否された場合、接続元制限の要求R05に対してはfailです。DB認証が残っていることを、想定したネットワーク境界の達成に置き換えません。

## M3の実行単位

T16で次を一つの実験計画へ固定し、承認後に実行します。

1. account/region/engine/version/instance class、認証方式、driver版、送信元と管理経路。
2. 正規主体、認証拒否用主体、DB user/schema、合成データだけを使う範囲。
3. 対象DBとProxy、SG、endpoint/port/address family、例外行列。
4. 許可する構築・DB SQL・書込・障害注入・資源削除の具体的対象と影響。
5. baseline、反復数、性能受入値、計測時刻・ウォームアップ・条件差。
6. 費用上限、実行時間上限、停止条件、片付け/復旧、保持する証拠。

未実行項目やunknownを残した場合、実施分と部分成果は報告できますが、必須条件を緩めてM3達成とはしません。意図的なDBフェイルオーバー等が対象に含まれない場合は、その未検証範囲を明示し、合意した復旧試験の範囲で評価します。

## 証拠の最低条件

run/要求/検証ID、証拠種別、対象、接続元、構成hash、snapshot参照、観測時刻、実行状態、理由コード、後条件を保存します。可能な正例と負例は同じ実行条件にまとめます。証拠に秘密・DB行・SQL値は保存しません。

CloudTrail等にIAM DB認証の記録が存在する前提を置きません。SDK/API、client TLS、DB応答、後条件、必要なAWS観測のうち、実際に取得できたものを記録します。単一の証拠から別区間や全主体の安全を推測しません。

## 今回の文書検証

リンク先ファイルと見出し、要求/検証/タスクID、依存関係の循環・欠落、全タスクの作業設計への対応を検査します。さらに、独立担当が偽pass、権限境界、共通契約、目的との整合をレビューします。これらは製品のビルドやAWS防御の試験ではありません。
